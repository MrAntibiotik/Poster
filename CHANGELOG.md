# Історія версій poster

Усі версії з комітами — у `releases.json` (оновлюється `python tools/make_releases.py`). Перейти на будь-яку: бот → «⬆️ Оновити» → «🕘 Версії / відкат»
(або /versions), панель → «🔄 Оновлення» → «Історія версій». Нові записи — зверху.

## 2026.11.19-172
- Instagram: якщо файл до Meta не дійшов (завантаження «400» і на сервері Meta 0 байтів), програма не чекає добу завислий контейнер, а через 30 хв вантажить відео наново, ще раз — через годину; якщо й тоді не вийде — повне відео вам у Telegram. Дубля бути не може: у старому контейнері відео немає. Підстава — історія: #54, #55, #63 зависали, а нове завантаження пізніше проходило

## 2026.11.19-170
- Instagram: одна логіка для звичайної, «тихої» і фонової публікації — один контейнер, одне очікування. Статуси: FINISHED → публікація; IN_PROGRESS / PENDING / невідомий → чекаємо той самий контейнер; ERROR / EXPIRED → лише тоді інший спосіб; PUBLISHED → без повторної публікації; помилка media_publish → повтор того самого контейнера
- Тайм-аут очікування більше не створює нового контейнера; ID контейнера зберігається одразу після створення — перезапуск не вантажить відео вдруге
- Прибрано внутрішнє обмеження «понад 55 с — лише вручну»; перевірка тривалості за офіційними межами Reels API (3 с – 15 хв). Копія для Instagram, як і раніше, до 59,5 с (шортси до 60 с) — тепер це налаштування «Максимальна тривалість для Instagram» у панелі (0 — не обрізати); сумісний оригінал до 59,5 с іде без перекодування; копії перестворюються

- Діагностика: усі перевірки статусу з часом, x-fb-trace-id / x-fb-debug, звук, час створення контейнера, категорія проблеми (файл / завантаження / обробка Meta / media_publish) — у журналі контейнерів, /containers і /history; «🕐 Статус» показує ID контейнера й час очікування
